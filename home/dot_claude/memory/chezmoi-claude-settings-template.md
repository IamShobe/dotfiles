In the dotfiles repo (`~/.local/share/chezmoi`, GitHub `IamShobe/dotfiles`), `~/.claude/settings.json` is generated by `home/dot_claude/modify_settings.json.tmpl` — a chezmoi `modify_` script (Python) that merges a `MANAGED` JSON block over whatever is already on the machine. To change a Claude Code setting across machines, edit the `MANAGED` block in that template.

`model` is listed in `LOCAL_ONLY_KEYS`, so it stays per-machine. BlueBear hooks (command contains `bluebear`) are also preserved from the local file. Everything else in `MANAGED` is authoritative and overwrites the local value.

**Why:** Running `chezmoi add ~/.claude/settings.json` deletes the template and replaces it with a static snapshot. That also breaks `run_onchange_after_6-install-claude-plugins.sh.tmpl`, which does `include "dot_claude/modify_settings.json.tmpl"` — chezmoi then fails with "no such file or directory" on every command. Nothing about the target file signals it is templated, so this is easy to hit twice.

**How to apply:** Use `chezmoi re-add` instead of `chezmoi add` — re-add explicitly "will not overwrite templates" (verified on v2.52.1: the `.tmpl` is left byte-identical), so it is safe by default across this whole repo, not just this file. To change a managed setting, edit `home/dot_claude/modify_settings.json.tmpl` directly and verify with `chezmoi cat ~/.claude/settings.json`.

If `chezmoi add` was already run and ate the template, recover with `rm home/dot_claude/settings.json && git checkout home/dot_claude/modify_settings.json.tmpl`.

Do not build a custom PreToolUse hook to guard this — upstream `re-add` already covers it, and a hand-rolled guard also wrongly blocks the safe `re-add` command.

Note `chezmoi add`/`apply` need `--force` in this environment — chezmoi cannot open a TTY for its confirmation prompt and errors with "could not open a new TTY".
